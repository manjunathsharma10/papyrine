# Spike 0.4: form scripts

Status: **done 2026-10-02.** Result: **the v0.1 forms plan (ADR-006) is confirmed.**
IRS-type forms are covered 100% (target ≥ 90%); the figure for everything else
is **62%** of real-world JS forms (published, as ROADMAP 1.13 requires).

Code: `crates/papyrine-forms` (zero dependencies). Corpus manifest:
`corpus/js-forms.toml`. Analysis scripts: `spikes/forms/`.

## 1. What was built

| Piece | File | Notes |
|---|---|---|
| Tokenizer | `src/lexer.rs` | Strings with escapes (`\x`, `\u`, surrogate pairs, octal, line continuation), numbers (decimal, exponent, hex), identifiers, punctuation, comments. Size and token caps. |
| Strict recognizer | `src/recognize.rs` | Only `AFname(literal, …);` sequences. Literals: string, number (with sign), `true`/`false`, `new Array(…)`, `Array(…)`, `[…]`. Newline acts as a terminator. Per-function arity and argument kinds. Anything else is `Reject`, never partly run. 256-statement and 1,024-argument caps. |
| Adobe boilerplate | `src/boilerplate.rs` + `boilerplate_table.in` | FNV-1a over the **normalised token stream**: strings and numbers become placeholders, comments and whitespace vanish in the tokenizer, runs of `ADBE.<name> = "<string>";` collapse to one marker. 8 Adobe shapes + 1 benign non-Adobe shape. |
| AF functions | `src/numfmt.rs`, `datefmt.rs`, `special.rs`, `calc.rs` | `AFNumber_Format/Keystroke` (nDec, sepStyle 0-4, negStyle 0-3 incl. red text colour, currency + prepend), `AFPercent_*`, `AFDate_Format/FormatEx/Keystroke/KeystrokeEx` (14-entry index table), `AFTime_*` (4-entry table + Ex), `AFSpecial_Format/Keystroke/KeystrokeEx` (zip, zip+4, phone, SSN, masks `9 A O X`), `AFSimple_Calculate` (SUM PRD AVG MIN MAX), `AFRange_Validate`, plus `AFMergeChange`, `AFMakeNumber`, `AFParseDateEx` as library functions. |
| Event model | `src/event.rs` | `value`, `change`, `selStart/selEnd`, `willCommit`, `rc`, target name, `textColor`, alerts as a typed enum (hosts can localise), `FieldLookup` trait. |
| Calculation order | `calc::run_calculation_order` | Runs each field's calculate script once in `/CO` order; later scripts see earlier results; throwing scripts leave their field alone. |
| Classifier CLI | `examples/classify.rs` | JSON lines in, verdicts out (`empty`/`accepted`/`boilerplate`/`rejected`, blocker category, fingerprint). Also smoke-runs every accepted script in format, commit and keystroke modes. |

Size of the Rust: ~3,000 lines of library (tokenizer + recognizer ≈ 880), ~2,800 of
tests and example. Measured on macOS arm64 with the workspace release profile
(thin LTO, strip): tokenizer + recognizer + boilerplate + classifier add **≈ 50 KB**
to a stand-alone binary (ADR estimate: < 100 KB); the whole crate including the
AF executors adds **≈ 150 KB**, most of it Rust's float-formatting code that any
app already contains. The ADR's parser estimate holds; the full-runtime figure is
a little above it in isolation.

Tests (`cargo test -p papyrine-forms`): 18 unit, 501 reference cases (§5), 6
robustness (> 120,000 random, mutated and extreme scripts plus ≈ 1.8 million
runtime executions per run, release and debug, no panic, no hang), 5 calculation-order. `cargo clippy --all-targets -D warnings`
and `cargo fmt` are clean.

## 2. Corpus

Fetched with `spikes/forms/fetch.py` into `corpus/cache/js-forms/` (gitignored;
390 MB). Nothing downloaded is committed.

* 1,108 PDFs downloaded: IRS, OPM, USCIS, State Dept, CMS, courts, DOL, USPS,
  FDA (US federal); CA, NY, FL, TX, IL, OR, OK (US states); gov.uk (UK); CRA
  (Canada); Home Affairs (Australia); the pdf.js test corpus.
* 710 are real-world forms (not pdf.js); 594 of those have an `/AcroForm`.
* **415 contain JavaScript** and are listed in `corpus/js-forms.toml`
  (391 real-world + 24 from pdf.js, pinned to a commit and hash-verified):
  IRS 147, USCIS 57, CA 40, OPM 38, NY 35, gov.uk 27, pdf.js 24, Home Affairs 8,
  CRA 7, TX 7, US Courts 6, CMS 5, IL 4, State 4, DOL 3, FDA 1, OK 1, OR 1.
* Of the 391 real-world JS forms, 219 are XFA hybrids (filled via their AcroForm
  side, XFA-internal scripts not counted) and 116 are encrypted with an empty
  user password (all opened).
* **Not reachable from this environment:** VA (DNS), SSA, DoD, ATF, NRC, Utah
  (HTTP 403 to non-browser clients), IRCC and ATO (connection refused or 404).
  The ADR's earlier note that SSA and VA were blocked still stands. Canada is
  therefore represented only by seven CRA forms.

Scripts were extracted with the `qpdf` CLI (`--json=2 --json-stream-data=inline`,
test-time tool only) by `spikes/forms/extract_scripts.py`: field actions
(`/AA` K F V C and the others), document-level JavaScript name tree,
`/OpenAction`, catalog/page `/AA`, widget/link/annotation `/A`, `/Next` chains
and unattached JavaScript actions. 21,589 non-empty scripts in 415 forms.

## 3. Results

"Covered" means the recognizer accepts **every** non-empty script in the form
(pure AF calls, or a known boilerplate shape, or empty). It says nothing about
behavioural parity; that is §5.

### 3.1 Against ADR-006's preliminary numbers

| Measure | ADR-006 (136 forms) | Spike 0.4 (415 forms) | Spike 0.4, real-world only (391) |
|---|---|---|---|
| Non-empty scripts that are pure AF calls | 57% | 72% (15,518 / 21,589) | 72% |
| JS forms covered, strict subset only | 8% | 15% (61 / 415) | 15% (57 / 391) |
| **JS forms covered, subset + boilerplate** | **93%** (125 / 134) | **74%** (306 / 415) | **76%** (298 / 391) |
| IRS | 111 / 111 | **147 / 147** | |
| New York | 7 / 7 | **35 / 35** | |
| OPM | 7 / 15 | 19 / 38 (50%) | |
| USCIS | 0 / 1 | **56 / 57** | |
| **Excluding IRS** | **61%** (14 / 23) | 59% (159 / 268, incl. pdf.js) | **62%** (151 / 244) |

The headline fell from 93% to 76% only because the sample is no longer 80% IRS.
The like-for-like "excluding IRS" figure for real-world forms is unchanged (61% → 62%). The 726
boilerplate scripts sit in 266 forms (IRS 147, USCIS 56, CA 36, CRA 7, DOL 3,
NY 5, OPM 6, TX 1, FDA 1, pdf.js 4); without the boilerplate recognizer IRS
coverage would be 0%.

| Trigger | accepted | boilerplate | rejected |
|---|---|---|---|

Format and keystroke are where the native subset works (99.6% and 96.5% of scripts). Validate,
calculate and button scripts are almost all custom. Only 35 `AFSimple_Calculate`
calls exist in the corpus (9 forms) against 198 calculate scripts overall; most
real calculations are hand-written.

### 3.4 What the accepted scripts use

`AFNumber_Format`/`Keystroke` 5,868 / 5,848 (119 forms), `AFDate_FormatEx`/
`KeystrokeEx` 1,413 each (98 forms), `AFSpecial_Format`/`Keystroke` 326 each
(65 forms), `AFSpecial_KeystrokeEx` 253 (27), `AFSimple_Calculate` 35 (9),
`AFRange_Validate` 16 (5), `AFDate_Format`/`Keystroke` 9 each (3), `AFTime_Format` 2.
`AFPercent_*`, `AFTime_Keystroke` and `AFTime_FormatEx` do not occur at all. No
allowlisted call was rejected for arity or argument shape, and none of the 15,518
accepted scripts throws when run in format, commit or keystroke mode.
No non-allowlisted `AF*` function occurs in a rejected script.

### 3.5 Why the rest is rejected (real-world forms; 93 of 391 not covered)

| Blocker (primary category) | Scripts | Forms with ≥ 1 | Forms freed if this alone were supported |
|---|---|---|---|
| Field access (`this.getField(…)`, `.value =`, `setFocus`) | 3,978 | 61 | 33 |
| Regex / string methods (`RegExp`, `.test`, `.replace`) | 652 | 41 | 22 |
| Other (assignments to globals, array literals + helper calls) | 170 | 14 | 0 |
| Control flow without a more specific marker | 268 | 9 | 4 |
| `event.*` manipulation (`toUpperCase`, `event.change = …`) | 85 | 5 | 0 |
| Custom functions (`AutoTab(…)`, document-level `function`) | 71 | 5 | 0 |
| `app.*` (`alert`, `response`, `runtimeHighlight`) | 41 | 7 | 1 |
| Navigation (`app.launchURL`, submit, print) | 16 | 3 | 1 |
| `util.scand/printd` | 10 | 1 (USCIS I-9) | 0 |

The ADR's two named blockers are confirmed and quantified: OPM-style checkbox
mutual exclusion (`this.getField(…).value = …` in `if` blocks) and I-9's custom
date validation. Newly visible: CMS-855 forms (≈ 2,200 field-access scripts in
four forms), UK gov.uk regex validators (CN_SSN_COMMIT shape, 488 scripts),
Home Affairs auto-tab control flow, and California FTB `makeExclusive` helpers.

### 3.6 What a cheap second tier would buy

Seven narrow, exact-shape recognizers (no JS engine) cover many of the rejected
scripts. They were counted by regex over whitespace-normalised script text, so
this is an upper-bound estimate, not an implementation:

| Pattern | Scripts | Forms | Additional forms fully covered |
|---|---|---|---|
| Checkbox mutual exclusion (`var A = this.getField("…"); if (A.value == "1") { B.value = "0"; }`) | 3,284 | 25 | 17 |
| `makeExclusive(ButtonNameArray)` calls + helper | 184 | 14 | 1 |
| `event.target.fillColor` highlight on non-empty | 244 | 7 | 3 |
| Focus a field (`getField("x").setFocus()`) | 379 | 2 | 2 |
| `if (event.value == 0) event.value = ""` | 23 | 2 | 1 |
| `event.value/change = … .toUpperCase()` | 85 | 5 | 0 |
| `app.launchURL("literal")` | 13 | 2 | 0 |

With them, real-world coverage goes from 298 to **322 of 391 (82%)** and excluding
IRS from 151 to **175 of 244 (72%)**. The remaining 69 forms need a real engine
(ADR-006 option (b)): CMS-855, gov.uk and Home Affairs validators, CA FTB
helpers, USCIS I-9.

Partial coverage is also informative: 316 of 391 real-world forms (81%) have
≥ 90% of their scripts covered, 353 (90%) have ≥ 50%. Executing the covered
scripts per field and bannering the rest is better than all-or-nothing per form.

## 4. Method and reproduction

```
python3 spikes/forms/fetch.py                       # 1,108 PDFs -> corpus/cache/js-forms/ (+ _fetch.json)
python3 spikes/forms/extract_scripts.py scripts.jsonl corpus/cache/js-forms/*.pdf
cargo run --release -p papyrine-forms --example classify -- scripts_only.jsonl > verdicts.jsonl
python3 spikes/forms/analyze_corpus.py scripts.jsonl verdicts.jsonl corpus/cache/js-forms/_fetch.json --json analysis.json
python3 spikes/forms/make_manifest.py scripts.jsonl corpus/cache/js-forms/_fetch.json corpus/js-forms.toml --pin-pdfjs
```

Extraction of all 1,108 files takes ≈ 27 s on an M4 (8 qpdf processes). Classifying
21,589 scripts (including the smoke run of every accepted script) takes 0.28 s
single-threaded. `corpus/fetch --list` accepts the manifest (415 entries). Local
files live under `corpus/cache/js-forms/`; `corpus/fetch` would place them under
`corpus/cache/files/js-forms/`.

Caveats:

* Government URLs are "latest" links; a republished form changes its hash and
  `corpus/fetch` will then fail hard. Regenerate the manifest if that happens.
* The corpus skews to US government forms because those are what is reachable here.
  Commercial and non-US forms (banks, insurers, HR packs, EU authorities) are
  underrepresented; expect a lower rate there.
* Classification of the *reason* (blocker) is heuristic and reporting-only;
  acceptance is decided by the strict recognizer alone.
* "Forms covered" counts a form as uncovered if one rarely used button script is
  rejected. §3.6 gives the partial-coverage view.

## 5. Behaviour reference (ROADMAP 1.13: ≥ 200 AF cases)

Acrobat was not available, so the reference was built from public sources and
every case names its source. **501 cases**, all passing
(`crates/papyrine-forms/tests/af_reference.rs`; the PDFium Format cases are
generated into `tests/data/pdfium_format_cases.in` by `spikes/forms/gen_pdfium_cases.py`).
Set `AF_REF_DUMP=path` when running the tests to write the full table with sources.

| Source | Cases | What it is |
|---|---|---|
| `pdfium:public_methods.in` | 258 | PDFium's BSD-3 test `testing/resources/javascript/public_methods.in`: percent matrix (value × nDec × sepStyle × prepend), number, date, special, calculate, range, keystroke commits, `AFMergeChange`, `AFMakeNumber`. PDFium reimplements Acrobat's AF functions and annotates several of these as matching Acrobat. |
| `pdfium:cjs_publicmethods_embeddertest.cpp` | 22 | Date parse/print tables (`ddmmyyyy`, `yymmdd`, two-digit-year pivot…). |
| `pdfium-src:*` | 89 | Derived by reading `fxjs/cjs_publicmethods.cpp` (rounding correction 1e-15, keystroke rules, mask rules, PRD/MIN/MAX start values). These are PDFium behaviour, not independent Acrobat evidence. |
| `adobe:*` | 132 | Adobe JavaScript for Acrobat API Reference semantics: the `sepStyle`, `negStyle`, `AFDate_Format` and `AFTime_Format` tables, `AFSpecial` kinds, `util.printd` tokens. Expected values were **derived by hand from the documentation, not captured from a running Acrobat.** |

By family: PDFium-generated Format cases 229 (percent matrix, number, date,
special, calculate), number format 45, percent 6, date format 32, time 13, special
format 14, date/time parse and print 37, number keystrokes 19 + commits 8 + percent
commits 2, special keystrokes 19 + commits 9, date commits 12, time commits 6,
range 15, calculate 19, merge 10, makeNumber 6.

**Where references disagree or we deviate on purpose (7 cases, marked `DISAGREE`):**

| Case | PDFium | Papyrine (chosen) | Why |
|---|---|---|---|
| `AFNumber_Format` sepStyle 4 | falls back to style 0 | `1'234'567.89` | Acrobat documents style 4; PDFium's own percent code honours it |
| `AFNumber_Format` negStyle 1 | no sign, red | `-1,234.50`, red | Acrobat's UI shows the minus in red; style 1 is the only one PDFium leaves unsigned |
| `AFDate_FormatEx` on `x` with `m/d` (L166) | prints today's date | keep text, invalid-date alert | a non-date is not today |
| `AFDate_FormatEx` on `20122015` (L170) | falls back to today | keep text, alert | same |
| `02/29/2023` | rolls over to 03/01/2023 | rejected, alert | Acrobat's message says the date must exist; **unverified** |
| 12-hour clock, hour 0 | `0:05 am` | `12:05 am` | 12-hour clocks have no hour 0 |
| 12-hour clock, hour 12 | `12:00 am` | `12:00 pm` | PDFium tests `hour > 12` |

Skipped PDFium lines, with reasons: 164/165 (numeric or nonsense *format*
argument coerced by JS; outside the strict grammar), 518/521 (pass only through
JS loose equality `'' == 0`), 237-239 (extra trailing arguments, which Acrobat
ignores and the recognizer rejects by design; none occur in the corpus).

Not modelled: `GMT`-style `Date.toString` values (PDFium's `ParseDateAsGMT`),
V8's full `Date.parse` (a documented subset is used: ISO, `M/D/Y [h:mm[:ss] [am|pm]]`,
month names), time zones, locale month names, UTF-16 offsets for astral
characters, `AFPercent` apostrophes beyond style 4.

## 6. Verdict on the v0.1 plan

**Confirmed.**

* IRS-type forms (IRS, NY, CRA, USCIS, DOL, FDA): 249 of 250 covered (99.6%);
  target ≥ 90%.
* Everything else: **62%** of real-world JS forms (151 / 244), UK 22%, Australia
  0%, OPM 50%, US states 61%. This is the published figure.
* The ADR's native subset and boilerplate recognizer behave as predicted; the
  surprise is how little calculation uses `AFSimple_Calculate` (35 calls) and how
  much uses hand-written scripts, which is what limits the non-IRS number.

### Proposed ADRs (for the lead to fold in)

1. **ADR-006 amendment: boilerplate fingerprint definition.** Strings and numbers
   normalised, `ADBE.<name> = "<string>";` runs collapsed, FNV-1a over the token
   stream, exact match on the whole script. Nine known shapes today (eight Adobe
   version/XFA-check shapes plus the inert California `onOpen()` that sets
   `nocache`/`noautocomplete`). New shapes are added by reading the script, not
   by loosening the match.
2. **ADR: AF behaviour deviations from PDFium** (the seven rows in §5). Settle
   the unverified ones by running `python3 spikes/forms/make_acrobat_check_form.py` (writes `corpus/cache/generated/acrobat-check.pdf`; open it in Acrobat Reader and compare each field with the printed columns) before 1.0. The form itself has not been opened in Acrobat yet.
3. **ADR: execute per script, banner per form.** Run every accepted script, leave
   rejected ones inert, and list what did not run in the banner, rather than
   disabling scripts for the whole form when one is unsupported. 81% of forms
   have ≥ 90% of scripts covered.
4. **ADR (v0.4/v0.5, `form-scripts` component decision):** add the "second tier"
   of exact-shape pattern recognizers (§3.6) before committing to QuickJS: +24
   forms (+6 points, +10 points excluding IRS) for a few hundred lines. Re-measure;
   the engine is then needed for ≈ 18% of forms rather than 24%.
5. **Calculation semantics:** each calculate script runs once per change in `/CO`
   order; fields outside `/CO` are not recalculated; a throwing script leaves its
   field unchanged. The host decides when to trigger.

### Open follow-ups

* Owner to open `acrobat-check.pdf` (generated, see ADR 2 above) in Acrobat Reader to settle the unverified
  deviations (leap-day rejection, `m/d/yy` fed a four-digit year, rounding of exact
  ties such as `1234.5` with 0 decimals, which Rust and C format half-to-even).
* Reach VA, SSA, DoD and IRCC forms (blocked here) from CI or the owner's machine.
* Wire `papyrine-forms` into `papyrine-engine`: field model implementing
  `FormValues`, `DateEnv` from the host clock, selection offsets in UTF-16.
* Add a `cargo-fuzz` target (the random-input tests run in CI already).
* Decide whether to accept extra trailing arguments (Acrobat ignores them; none
  occur in the corpus).
