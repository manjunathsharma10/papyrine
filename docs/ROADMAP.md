# Folio — Roadmap

Status: **Draft for approval** · Last updated: 2026-09-30

Nine phases, in the order the spec's Section 14 gives them. Every phase ends
with:

- an installable build for macOS (verified locally), with Windows and Linux
  verified in CI;
- green CI;
- a `docs/PHASE_N_REPORT.md`.

Phase 1 is broken into detailed tasks. Later phases are listed at task level
and will be refined into the same detail (with a short addendum for your
review) when each phase starts.

**Legend:**
- **AC** = acceptance criteria. A task is done only when all its ACs pass in
  CI (or on the reference machine where noted).
- **Corpus** = the test corpus (task 1.3).
- **Interop check** = the output passes `qpdf --check`, renders without
  errors in PDFium, PDF.js and Poppler `pdftoppm`, and re-opens in Folio.

---

## Phase 1 — Foundation

**Goal:** a fast, robust, crash-safe **viewer** with search, document
properties, saving (incremental and full) and crash recovery, on a
production-grade engine, process and CI skeleton.

### 1.1 Repository and tooling
- Cargo workspace with the crates from ARCHITECTURE §3 (empty crates only
  where Phase 1 needs them); pnpm workspace; `rust-toolchain.toml`;
  `.editorconfig`; rustfmt, clippy, ESLint, Prettier and tsconfig configs in
  strict mode; `LICENSE-MIT`, `LICENSE-APACHE`, `README.md`, `SECURITY.md`,
  `CONTRIBUTING.md`.
- **AC:** `cargo build --workspace`, `cargo clippy -- -D warnings`,
  `pnpm typecheck`, `pnpm lint` and `pnpm test` all pass from a clean clone
  with the documented prerequisites.

### 1.2 CI and license gate
- GitHub Actions matrix: macOS arm64 and x64, Windows x64 and arm64, Ubuntu
  x64.
- `cargo-deny` configured with the ADR-001 allowlist and name bans, plus a JS
  license check.
- `THIRD_PARTY_LICENSES.md` generated by `cargo-about` plus a JS script; CI
  fails if it is stale.
- Dependency caching; build artifacts uploaded per OS.
- **AC:** CI green on all five targets. A deliberately added GPL test
  dependency on a scratch branch makes CI fail.

### 1.3 Test corpus
- `corpus/manifest.toml` lists files with source URL, SHA-256, license and
  tags (malformed, encrypted-aes256, scanned, cjk, rtl, huge, …).
- `corpus/fetch` downloads and verifies the files into a cache that CI caches.
  Sources: pdf.js test corpus, pdfium testing files, veraPDF corpus, Isartor.
- Generated files (`tools/gen-corpus`): a 2,000-page text manual; a 1,000-page
  image-heavy document; every encryption algorithm; truncated and xref-broken
  variants produced by deterministic mutation of clean files.
- **AC:** `corpus/fetch --verify` passes. The corpus has ≥ 500 files including
  ≥ 50 malformed. The license of every file is recorded.

### 1.4 `qpdf-sys` + `folio-cos`
- Vendored qpdf ≥ 11 built with CMake (native crypto, zlib-ng, libjpeg-turbo)
  on all targets.
- Safe wrapper covering:
  - opening from bytes, with or without a password (the password is
    zeroized);
  - object access (dict, array, stream, names, strings, numbers, refs);
  - stream data (raw and decoded), replacing stream data, creating objects;
  - unparse;
  - QPDFWriter options;
  - RepairLog capture.
- **AC:**
  - Every corpus file either opens or fails with a typed error. No panic,
    crash or hang (30 s timeout).
  - All generated-malformed files open and log a RepairLog entry.
  - Encrypted files for RC4-40, RC4-128, AES-128 and AES-256 open with the
    right password and are refused with the wrong one.
  - Unit tests for every public function.

### 1.5 `folio-content` (content stream lexer / parser / serializer, basic interpreter)
- Tokenizer per ISO 32000 §7.2 with tolerant recovery. Parser into ops with
  byte spans. Serializer with a precision option. Interpreter for the
  graphics and text state and XObject recursion (depth-limited), emitting
  glyph, image and path events.
- **AC:**
  - Round trip (parse → serialize → parse) is identical for every corpus
    content stream.
  - A fuzz target runs 10 min in CI with no crash. Nightly fuzzing runs for
    1 h.
  - Property tests for number formatting.

### 1.6 `folio-model` (read side)
- Page tree with inheritance; boxes; rotation; page labels; outlines (with
  destinations resolved); name trees; Info and XMP; fonts inventory
  (embedded, subset or not, type); attachments list; OCG list; struct-tree
  presence; encryption summary and permissions; signature fields list
  (read-only); linearized flag; PDF version.
- **AC:** tests assert these values against expected values for 30 curated
  corpus files. The model never panics on the corpus.

### 1.7 `folio-ops` (commands, journal, history)
- `Command` trait, `EditContext` with before-images, `ChangeSet`, `History`
  with a memory budget, `CompositeCommand`.
- Phase 1 commands: set document metadata (Info + XMP synced), set initial
  view settings, set page labels (used by Properties).
- Rotate pages is also added as the first page command, so undo is exercised
  on real page edits. The rest of Organize is Phase 2.
- **AC:**
  - For each command: apply → revert gives objects byte-identical to the
    original.
  - apply → save → reopen shows the change. Interop check passes.
  - Undo/redo sequences of random command series (property test) restore the
    exact state.

### 1.8 `folio-writer`
- Incremental save (xref table or stream to match the original; handles
  encrypted documents; hybrid-reference files).
- Full rewrite via qpdf (object streams on, compress streams, preserve
  encryption by default).
- Linearized output option.
- Atomic replace routine with post-write validation.
- **AC:**
  - Incremental save of a signed corpus file leaves every original byte
    unchanged (prefix byte comparison), and pyHanko reports the existing
    signatures as intact, with the modification classified as an
    incremental update.
  - Interop check passes for all three modes on 100 corpus files.
  - A kill -9 injected at every step of atomic replace (test harness) never
    leaves the target corrupt or missing.
  - Save As to another volume works.

### 1.9 Render workers + tile pipeline
- PDFium bundled and pinned by hash.
- Render worker binary; render pool in the broker; tile math; zoom buckets;
  preview → sharp progressive rendering; priority queue with cancellation;
  L1/L2 caches; `folio://` scheme; shared-memory transfer; render snapshots
  (original + incremental delta).
- Worker crash recovery (the supervisor restarts it and re-issues pending
  requests).
- **AC:**
  - Pixel output matches golden PNGs for 50 corpus pages (perceptual diff
    ≤ threshold).
  - The perf harness on the reference machine meets:
    - first page < 500 ms (20 pages) and < 2 s (2,000 pages);
    - peak RSS across all processes < 500 MB viewing the 1,000-page
      image-heavy document through a full scroll.
  - Killing a worker mid-render recovers with no user-visible error beyond
    a brief re-render.

### 1.10 Process split + sandbox (initial)
- Engine and render workers as separate processes under a broker supervisor.
- macOS Seatbelt profile and Linux landlock + seccomp applied at child
  start-up.
- Windows restricted token + Job object, or else a documented slip to 2.0
  (see ARCHITECTURE §8).
- **AC:** a test binary run inside each sandbox tries to open `~/`, write to
  `/tmp`, open a socket, and spawn a process. Every attempt is denied. The
  normal render and engine paths still pass.

### 1.11 Desktop shell and viewer UI
- Tauri app; design tokens; light, dark and high-contrast themes; an original
  icon set (the Phase 1 subset); app layout (toolbar, left pane, document
  area, right pane, status bar); command palette; i18n scaffolding (all
  strings externalized, English catalog, RTL layout switch tested with a
  pseudo-locale).
- **Tabs,** multiple windows, drag tabs between windows. Open via dialog,
  drag and drop, recent files (with thumbnails, pinned, open recent folder),
  and OS "open with" / file associations.
- **View modes:** single, two-page (with or without cover), continuous,
  continuous facing, full screen / presentation (with PDF-defined page
  transitions where PDFium exposes them, and a fade fallback otherwise),
  reading mode.
- **Zoom:** fit page, fit width, fit visible content, actual size, 1%–6400%,
  marquee zoom, loupe tool, pinch/trackpad zoom.
- **Rotate view** (temporary) and rotate pages (saved), with distinct UI and
  labels.
- **Split view** (two panes of one document) and side-by-side view of two
  documents with synchronized scrolling.
- **Navigation:** thumbnails pane (virtualized); bookmarks pane (read-only in
  P1); attachments list (open or extract with a prompt); layers (toggle
  visibility, view-only); destinations; signatures list (read-only,
  "validation arrives in Phase 7"); tags tree (read-only view).
  The content order and model tree panes come with their feature phases
  (8 and 9) and are hidden until then, per the no-placeholder rule.
- Go to page, back/forward history, full keyboard navigation.
- Rulers, grid and guides (display only in P1; snapping is used from P3 on).
- Night mode, invert page colours, custom page background colour.
- **Document Properties dialog:** description (editable), custom metadata
  fields, XMP editor (form and raw), initial view settings (editable),
  security summary, fonts list, and version, producer, size, linearized and
  tagged flags.
- Read Aloud (page, from cursor, selection) via the OS TTS, following tag
  order when present.
- The repair banner; an external-change banner; action prompts (URI, launch,
  embedded file).
- **AC:**
  - E2E tests (Windows and Linux WebDriver, macOS Playwright bridge) cover:
    open, each view mode, zoom modes, tab drag between windows, split view,
    properties edit + save + reopen, keyboard-only navigation of every pane.
  - Scripted-scroll frame timing on the 2,000-page file: p95 frame time
    ≤ 16.7 ms on the reference machine.
  - The accessibility audit (axe-core) of the UI has no serious or critical
    violations.
  - Every UI string is present in the catalog (lint rule).

### 1.12 Search
- Find bar (whole word, case, diacritics, include bookmarks/comments).
- Advanced Search panel: current document, all open documents, or a folder
  (recursive), with results grouped by file and page, snippets, and streaming
  results.
- Search inside annotations' text, form field values, bookmarks,
  attachments' names and descriptions, and metadata.
- Regex mode.
- Ligature, hyphenation, RTL and CJK handling.
- Folder catalogue index (tantivy): pulled into Phase 1 only if 1.1–1.11 are
  complete, otherwise Phase 9. The UI hides it until it exists.
- **AC:**
  - Search over the 1,000-page file completes in < 3 s on the reference
    machine, with the first hit shown in < 300 ms.
  - Golden tests for ligature, hyphenation, Arabic, Hebrew, Japanese and
    Chinese queries.
  - Search is cancellable.

### 1.13 Crash recovery and autosave
- Autosave every 5 min (configurable) to `recovery/`.
- Recovery dialog on launch.
- **AC:** an integration test makes an edit, simulates a crash (kill the
  broker), relaunches, restores the changes, and saves; the output matches
  the expected document. Recovery is refused, with an explanation, if the
  original changed.

### 1.14 CLI (Phase 1 subset)
- `folio info [--json]`, and `folio validate --structure` (a parse and repair
  report, not yet PDF/A).
- Exit codes, `--json`, progress on stderr.
- **AC:** snapshot tests of the CLI output on 20 corpus files.

### 1.15 Phase 1 deliverables
- Unsigned `.dmg`, `.msi`, AppImage and `.deb` from CI; Flatpak manifest
  builds in CI.
- `docs/PHASE_1_REPORT.md` with measured performance numbers.

**Phase 1 risk register:**
- Windows sandbox testing on hosted runners.
- PDFium page transitions API coverage.
- Tab drag between windows in Tauri 2: it needs custom window-to-window drag
  handling. If a native limitation blocks it, I'll report back with options.

## Phase 2 — Organize and Compress

**Organize (spec §9)**
- 2.1 Page grid view with resizable thumbnails; drag reorder; multi-select;
  drag pages between documents and windows.
- 2.2 Insert from PDF, blank page, clipboard, and image files. Insert from
  Office arrives with the LibreOffice integration (P6); insert from scanner
  in P6.
- 2.3 Delete, extract (one file or per page), duplicate, replace (optionally
  keeping comments), rotate (ranges, odd/even).
- 2.4 Split by N pages, by size, by top-level bookmarks, by blank-page
  separators, or by ranges; naming templates.
- 2.5 Merge/combine with file and page reordering, bookmark merge or
  generation from filenames, and AcroForm merge with field-name collision
  resolution.
- 2.6 Crop tool; auto-remove white margins; numeric page boxes; change page
  size (scale content or extend canvas).
- 2.7 Page labels editor; reverse; interleave; N-up / booklet export.
- **AC:** round-trip + interop checks for every command. Undo is exact. A
  merge of 100 corpus files keeps outlines and form fields working.

**Compress (spec §10) — flagship**
- 2.8 `folio-codecs`:
  - mozjpeg encode (trellis, optimized Huffman, 4:4:4/4:2:0);
  - JPEG quality estimation from quantization tables;
  - OpenJPEG encode (lossy/lossless);
  - JBIG2 generic lossless and lossy text-region (jbig2enc);
  - CCITT G4 (fax);
  - Flate with PNG predictor selection;
  - resampling (bicubic, bilinear, area, Lanczos);
  - colour reduction detection (grey / bi-tonal);
  - ICC conversions (lcms2);
  - decoding of all PDF image filters, with PDFium used for JBIG2/JPX/CCITT
    decode where no permissive Rust decoder exists.
- 2.9 Space audit covering every §10.1 category; top-20 objects with
  click-to-locate; the per-image table (dimensions, effective DPI via the
  `folio-content` interpreter taking the max over usages, colour space, bpc,
  filter, bytes, bytes/pixel).
- 2.10 Optimization pipeline: every §10.3 technique as an individually
  toggleable pass:
  - images;
  - fonts: subset, merge duplicate subsets, un-embed with a warning, Type1 →
    CFF;
  - streams: Flate everything, LZW/ASCII → Flate, object and xref streams;
  - dedup by content hash;
  - garbage collection;
  - content-stream optimization with a precision tolerance;
  - repeated content → shared Form XObjects;
  - linearize;
  - every discardable-data category;
  - flatten transparency and annotations/forms.
  "Never bigger" per object. Generational-loss guard.
- 2.11 Presets (Lossless, Print, Balanced, Screen, Maximum, Custom with
  save/load) with a pre-run size estimate (sampled encode of the top images,
  extrapolated).
- 2.12 Target-size mode: a search over DPI × quality, largest images first,
  with a readability floor, reporting what it had to do.
- 2.13 Safety:
  - new file by default;
  - before/after report by category;
  - warnings;
  - discard the output if it is larger than the input;
  - PDF/A, PDF/UA and signature detection, with restricted technique sets or
    explicit warnings;
  - verification (re-parse, low-DPI render of every page, SSIM vs original,
    optional veraPDF).
- 2.14 Visual diff preview (synchronized zoomable before/after, blink,
  difference overlay).
- 2.15 Batch compression UI (folders, parallel, per-file progress, CSV
  report). CLI `compress` and `audit` with all options, plus `merge` and
  `split`.
- 2.16 Compression benchmark in CI; `docs/COMPRESSION.md`.
- **AC:**
  - Every technique has unit tests and a benchmark contribution.
  - On the benchmark set, Balanced output passes the interop check with mean
    SSIM ≥ 0.97 (per-page min ≥ 0.92).
  - The 100-page 300 dpi colour scan compresses in < 60 s on the reference
    machine.
  - Sizes are compared against qpdf-only, pikepdf-only and (if supplied)
    Acrobat reference outputs, with results in `docs/COMPRESSION.md`.
  - MRC for scans is **Phase 6** (it needs OCR-grade segmentation, per the
    spec's phase list). The Phase 2 presets handle scans with downsampling,
    JPEG/JP2 and bi-tonal JBIG2 conversion.

**Early Phase 2:** carry-over of the Windows sandbox if it slipped from 1.10.

## Phase 3 — Comment and Fill
- 3.1 Annotation model and commands for every type in spec §7, with appearance
  stream generation matching Acrobat round-trip conventions.
- 3.2 Tools UI: each markup tool; snapping; properties panel (author, colour,
  opacity, border, cloudy, lock, flags, subject, dates, status, check marks);
  threaded replies; pressure-sensitive ink via Pointer Events pressure.
- 3.3 Stamps: dynamic built-ins, custom from image or page, library manager.
- 3.4 Comments pane: filter, sort, search, bulk operations. Comment summary
  PDF (4 layouts).
- 3.5 FDF/XFDF import and export; import comments from another version of the
  file (page matching by content hash, then position).
- 3.6 Flatten (per type). Show/hide, connector lines, pop-up preferences.
- 3.7 Fill & Sign: type anywhere, marks, line snapping (layout analysis),
  date and initials; electronic signature (type, draw, image) with profiles
  in the OS keychain.
- 3.8 AcroForm filling for existing forms (no JS yet; JS arrives in P5).
  Appearance regeneration and NeedAppearances handling.
- **AC:**
  - Round trip with Acrobat-produced annotation samples in the corpus.
  - Annotations render in PDF.js, Poppler and PDFium.
  - XFDF round trip preserves every property.

## Phase 4 — Edit
- 4.1 Layout analysis: text blocks, paragraphs, columns (`folio-text`) and a
  golden-set evaluation.
- 4.2 Paragraph text editor: font preservation; missing-glyph fallback chain
  with a user notice; re-subsetting; formatting controls; lists; super- and
  subscript; reflow within the box; vertical writing; Type 1, TrueType,
  CFF, Type 3 and CID fonts; ToUnicode.
- 4.3 New text boxes; spell check (NSSpellChecker, Windows ISpellChecker,
  spellbook); find and replace as content edits with a preview.
- 4.4 Image and object editing (move, resize, rotate, flip, crop, replace,
  extract, delete, arrange/align/distribute, add from file or clipboard;
  vector path recolour and stroke; edit in an external app with re-import);
  object inspector.
- 4.5 Headers and footers; watermarks; backgrounds; Bates (multi-file);
  links (with URL auto-detect); a bookmarks editor (plus auto-generation
  from tags or headings); a layers editor; an attachments editor. All
  tool-added artifacts are tagged for update and removal (Acrobat-compatible
  PieceInfo / marked-content conventions).
- **AC:**
  - Edit-and-save tests on 50 real documents: text is extractable and
    correct afterwards.
  - Visual regression outside the edited region is ≤ threshold.
  - Font substitution is always reported to the user.

## Phase 5 — Forms and Protect
- 5.1 Prepare Form: auto field detection (boxes, lines, checkboxes, grids)
  with suggested names; every field type; the full property set; formats;
  validation; calculations (built-ins, simplified field notation, custom JS);
  actions; visual tab-order editor; duplicate, grid copy, align, match size.
- 5.2 Form JS runtime (QuickJS, sandboxed, with the Acrobat form API
  surface). Tested against the corpus of Acrobat JS forms.
- 5.3 Form data import/export: FDF, XFDF, XML, TXT/CSV; merge data files into
  a spreadsheet; highlight, reset, clear, flatten.
- 5.4 Encryption: AES-256 (default), AES-128, RC4-128 (with a warning); the
  scope options; all permissions; certificate (public-key) encryption;
  remove security.
- 5.5 True redaction: mark text, areas and pages; search-and-redact with
  patterns and word lists; apply by rewriting content streams (glyph
  removal with positioning compensation), image pixels, vector paths, form
  values, annotations and hidden OCR text; overlay appearance and codes;
  permanent warning; new file by default.
- 5.6 Sanitize / remove hidden information: a checklist with counts; removal
  of previous revisions (forced full rewrite).
- **AC:**
  - Redaction leakage suite: extract text, images, raw streams and every
    revision from the output, and assert zero occurrences of the redacted
    content.
  - Encryption output opens in PDF.js, Poppler and qpdf.
  - The JS sandbox escape test suite passes.

## Phase 6 — Scan, OCR, Create, Export
- 6.1 Tesseract integration, language packs (downloaded on explicit user
  request, checksum-verified), searchable-text mode, editable-text mode,
  suspect-word review, skip of pages that already have text.
- 6.2 Scan enhancement: deskew, auto-rotate, background whitening, border
  removal, despeckle, contrast, perspective correction.
- 6.3 **MRC compression** (foreground mask JBIG2, background JPEG/JP2,
  foreground colour layer) with optional OCR, added to the compression
  presets.
- 6.4 Scanner support: WIA/TWAIN, ImageCaptureCore, SANE (runtime), with
  presets.
- 6.5 Create PDF from images (all formats; HEIC via OS codecs), from Office
  (LibreOffice detection and guidance), from HTML and web pages (platform
  webview print-to-PDF), and from the clipboard.
- 6.6 Export to DOCX, XLSX, PPTX (layout reconstruction), RTF, TXT,
  accessible text, HTML, XML, Markdown, and images (PNG, JPEG, TIFF
  multi-page, WebP); export all images.
- **AC:**
  - OCR word accuracy ≥ 95% on the clean-scan benchmark.
  - MRC achieves ≥ 5× reduction vs Balanced on colour scans with OCR text
    still correct.
  - A DOCX export evaluation set (text order, tables, images), with
    documented known limitations.

## Phase 7 — Sign and Compare
- 7.1 Digital IDs: PKCS#12, the Windows store, macOS Keychain, PKCS#11;
  self-signed ID creation.
- 7.2 Signing: adbe.pkcs7.detached and ETSI.CAdES.detached; PAdES B-B, B-T
  (RFC 3161), B-LT (DSS with OCSP/CRL), B-LTA (document timestamps);
  appearances; certification (MDP); incremental only.
- 7.3 Validation: byte range, chain building (OS trust store plus user trust
  list, optional EUTL/AATL import), OCSP/CRL (online and offline),
  timestamps, post-signing modification analysis, view the signed revision;
  a signatures panel with reports.
- 7.4 Compare files: text diff (insert, delete, replace), formatting, images,
  annotations, page insert/delete; synchronized view; filters; comparison
  report PDF; pixel-compare mode with overlay and blend.
- **AC:**
  - pyHanko and EU DSS validate Folio signatures at every PAdES level.
  - Folio validates the corpus of third-party signed files with results
    matching the reference validators.

## Phase 8 — Standards and Accessibility
- 8.1 PDF/A (1b, 2b, 2u, 3b, 3u, 4) conversion and validation; our rule
  engine checked against veraPDF on its corpus; auto-fixes.
- 8.2 PDF/X (1a, 3, 4) conversion and validation; PDF/E awareness.
- 8.3 Preflight: profiles, fixups, reports.
- 8.4 Output preview: separations, TAC, overprint, rich black, colour-space
  highlighting; convert colours; ink manager; printer's marks; hairlines;
  bleed; transparency flattening with preview.
- 8.5 Accessibility checker (PDF/UA-1, WCAG 2.2 PDF techniques) with fix and
  explain actions; autotag; Reading Order tool; tags tree editor; guided alt
  text.
- 8.6 Audit and harden the app's own accessibility (VoiceOver, Narrator/NVDA,
  Orca; high contrast; UI scaling).
- **AC:**
  - Folio's PDF/A output passes veraPDF.
  - Our validator agrees with veraPDF on ≥ 99% of the Isartor and veraPDF
    corpus verdicts.
  - Autotagged Matterhorn samples pass the PDF/UA machine checks.

## Phase 9 — Automation and Polish
- 9.1 Action Wizard: step builder over the command registry, runtime
  prompts, run on files or a watched folder, built-in actions, macro
  recording from the Command log, JSON import/export.
- 9.2 Measure tools (distance, perimeter, area, snapping, scale, measurement
  dictionaries, geospatial coordinates, CSV export).
- 9.3 Portfolios (browse, extract, create); rich media playback or extract;
  3D poster fallback; model tree pane.
- 9.4 Printing: native dialogs, every scaling mode, N-up, booklet,
  poster/tiling, print as image, duplex, grayscale, paper source, accurate
  preview.
- 9.5 Full CLI (every spec §13 command); localization framework completion;
  performance tuning; shortcut editor with a printable cheat sheet;
  preferences completeness.
- 9.6 Installer signing and notarization (when certificates exist);
  auto-update (Tauri updater, signed manifests); in-app searchable help plus
  the user guide as a PDF generated by Folio itself.
- **AC:** the spec §18 Definition of Done, verified item by item in
  `docs/PHASE_9_REPORT.md`.

## Cross-cutting, every phase
- New commands: unit, round-trip, interop and undo tests.
- New parsers or decoders: fuzz targets.
- New dependencies: license gate and an ADR if the dependency is significant.
- `docs/DECISIONS.md` updated.
- The phase report lists deviations from this plan.
- Commits are pushed to GitHub regularly (at least at the end of every task).
